Authentication
--------------
- No Clerk runtime, Clerk cookies, Clerk keys, or test-user header bypass.
- Passwords use salted scrypt hashes, never plaintext in the account store.
- Seven-day HMAC-signed Secure/HttpOnly/SameSite=Lax cookie, host-only.
- Roles and names come from the server-side account file, not browser input.
- Password changes invalidate older signed sessions through sessionVersion.
- Sign-out clears the browser cookie. A previously copied signed cookie remains valid until expiry or password rotation; sessions are not a central revocation database.
- Password changes are available at /account after sign-in.
- No public self-registration or email password-reset flow.
- Login is rate-limited; mutating browser API calls are same-origin guarded.
- API data is no-store; old api-cache is deleted and new service worker does not cache API responses.
